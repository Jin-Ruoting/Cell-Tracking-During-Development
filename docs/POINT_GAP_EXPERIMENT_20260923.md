# E038：独立点检测器支持的一帧断轨桥接

本方案在首个 E038 图分数产生前固定。假设是：已有轨迹两端的运动一致性与
第二个检测器的真实观测，共同筛出少量可信缺点，能以较小的节点代价增加正确边。
对照固定为 E029；不加入 E031、E035 或其他未通过的组件。

## 输入与固定算法

复用 [hengck23 点检测器](https://www.kaggle.com/code/hengck23/cell-point-detector)
已完成的 64 部 CUDA 缓存，保持作者的输入尺度、归一化、权重和抽峰方法。
模型训练影片排除情况仍未确认，本实验不是独立外部验证。
桥接规则由本项目独立实现，借鉴真实峰补断轨的思路，不声称完整复现作者跟踪器。

- 在 E029 **最终导出图**上补点，保留其所有节点、坐标与边；不重新过滤轨迹。
- 只补缺失一帧：终点与起点相隔两帧。两端各有两条连续、无分叉的上下文边，
  用这两步的平均物理位移作前向和反向预测。
- 峰概率至少 `0.5`，距缺失帧的所有已有节点大于 `2 um`。
  峰距两端的每步位移不超过 `5 um`；距端点中点和双向预测各不超过 `3.5 um`，
  两步都不能逆各自上下文速度方向。沿用此前观测补点的尺度，不扫描阈值。
- 若同一终点、起点或检测峰属于多个可行桥接，全部弃用，不按 GT 或局部得分选择。
  每个被接受的峰增加一个节点与两条连续边，禁止合成坐标、分裂补边与重复迭代。
- 新增节点不超过原节点数的 `3%` 向下取整；若超预算，按双向预测残差和、
  峰概率、原节点 ID 确定顺序。完整记录歧义、预算拒绝和新增计数。

这与 E034 的区别是作用于最终图、严格双向上下文和歧义弃用，不会通过后续
滤轨让一处补点额外保留整条轨迹。E034 的负结果保留，不能据此承诺 E038 获益。

## 验证与判定

1. 服务器先执行语义检查：真实观测要求、尺度、双向运动、冲突弃用、分叉保护、
   节点预算和原图逐字段不变。所有开发运行先完成本地提交、推送及服务器快进拉取。
2. 使用既定两部影片检查完整导出和评分接口；参数不随检查分数改变。通过技术
   检查后，以同一 CUDA 缓存运行固定 64 部影片，完成所有预测后才调用官方评分。
3. 核对 E029 CSV、GEFF 全树、既有精确重放和点缓存的哈希；逐影片保证完整覆盖，
   独立检查坐标边界、连续帧、单父节点、最多双子节点和原图保留。失败不得回退。
4. 沿用总分至少 `+0.001`、调整后边分数不降、两类胚胎及两半影片均改善、
   受影响影片胜多于负且中位增益为正的全部门槛。报告节点/边及分裂 TP/FP/FN。
5. 只有完整门槛通过后才进行作者选片排除审查、Kaggle 运行和实际输出审计；
   正式提交前核对每日五次额度，绝不重复提交 E035。公榜收益与开发分数分开记录。

复用缓存，无需再次占用 GPU 推理。两部检查和完整比较各设 30 分钟运行上限，
这是资源预算，不是已测时长。日志、桥接明细和提交文件只写入忽略的运行目录。
