# E039：Kaggle 同环境配对评估

本协议在首次桥接候选生成和评分前固定。E038 的历史服务器精确复现检查
仍为失败：首次 Kaggle 对照少 12 个节点、12 条边，官方分数相差约
`0.00001981`。其原因尚未确定，不把这项差异计作算法收益，也不覆盖原记录。

E039 单独检验已经固定的 E038 桥接机制在 Kaggle 上是否有效。对照与候选
共用**同一次推理产生并冻结的完整控制图**，候选只在它上面追加真实检测峰。
这允许直接估计追加操作的增益，不将不同计算环境的两个图相减。
[PyTorch 官方复现说明](https://docs.pytorch.org/docs/stable/notes/randomness.html)
指出跨版本、跨平台的精确复现不受保证；该说明不能证明本次差异的具体原因。

## 启动条件与不变量

- S210 必须在固定 T4 上重新推理，并精确复现 S209 的控制 CSV 和官方分数。
  这是云端稳定性条件，不改变 E038 历史服务器的哈希门槛。复测失败则不启动。
- 新实验使用独立私有 Notebook。提交、推送本地代码后才打包运行；不在本地
  推理，不直接修改服务器，不把凭据、日志、预测图或外部代码放进公开仓库。
- 仍用 E029 的原始 Notebook、三个权重及七项固定覆盖配置；仅允许两处日志
  路径变化。固定 Docker、T4 与依赖版本，记录源码和权重校验值。
- 使用同一历史 64 部影片及两部技术检查影片；清单哈希保持不变。GT 仅用于
  既有集合重建和最终官方评分，不能用于预测或桥接筛选。
- 候选完整沿用 [E038 规则](POINT_GAP_EXPERIMENT_20260923.md)：真实 v5 峰、
  一帧缺口、双向上下文、固定概率和距离门限、歧义弃用、3% 节点预算。
  不叠加 E031/E035，不扫描阈值，不重训或更换模型。

## 执行与冻结

1. 两片检查先重新生成云端控制，要求与 S210 CSV、依赖版本和官方分数精确
   一致；只检查技术流程，不根据其候选分数更改参数或决定是否跑完整集。
2. 固定 64 部运行先生成全部控制图并保存 CSV 哈希。核对其中两部检查影片
   与已冻结的云端控制图一致；比较节点坐标和边结构，允许导出行号或节点编号
   的整体平移，不允许坐标、节点、边发生实际改变。
3. 在读取候选图分数之前，完成全部 v5 缓存和全部桥接图，分别检查覆盖、
   概率、坐标边界、连续帧、单父节点、最多双子节点，以及原图逐字段保留。
   阶段间再次核对控制哈希；输入缺失或校验失败即停止。
4. 官方评分配对比较本次冻结控制和本次候选。完整集控制分数事先未知，
   如实记录，不要求它等于服务器的 `0.9090442379185286`，也不据此调参。
   同时复核两部锚点的官方控制分数，防止运行环境或评分器发生漂移。

## 固定判定与资源边界

- 只以完整 64 部结果判定：总分增益至少 `0.001`、调整后边分数不降、两类
  胚胎与交替两半均为正、受影响影片胜多于负且中位增益为正。任何一项失败
  都不晋级；报告节点/边、分裂 TP/FP/FN 和逐影片变化。
- 训练重叠仍未确认，结果始终标为开发证据。通过完整门槛后仍须完成既有
  作者选片排除审查、实际提交输出审计，再决定是否正式提交。公榜分数另行核实。
- 两片技术运行限两小时。完整运行预算由实际两片耗时和剩余额度确定，
  单次不超过 Kaggle 会话上限，不并发复制相同实验；不自动购买计算资源。
