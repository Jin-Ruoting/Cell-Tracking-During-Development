# E041：固定 HOCT v0 权重的上游尺度修复

在首次修复版真实图像推理和质量评分前固定。假设是：候选邻居与模型特征使用
上游明确的尺度约定后，HOCT 对 E029 普通边的独立共识更可靠。只替换
[官方修复](https://github.com/royerlab/hoct/pull/6)的三个文件，不同时更换权重。

## 冻结输入与机制

- 服务器原始 E029 CSV SHA256 为
  `1d4fd28c02cb54d2279a120794b26e21fa0741d743bf62781d8ed17d5a26e2ce`，
  完整官方控制分数为 `0.9090442379185286`；保留独立重放与原 GEFF 哈希。
  与 Kaggle 控制不同，不能把其微小平台差异计为本方法收益。
- 复用完成的 S197 中不可变节点输入和旧 v0 共识缓存，核验全部输入数组、
  文件哈希、完整 100 帧、来源提交及版本。旧 v0 对照是已完成缓存，明确
  记录复用，不声称此次重新推理。新候选只读取图像和这些固定节点。
- 权重仍为 `general_v0.pt`，SHA256
  `024c2e4606275c96667907abfc9e0c27487b543480caf99d9ebd1d267cef8e4a`。
  HOCT wheel 仍为 0.2.0，只加载固定提交
  `8709ee9d3c4d7aae1f022b259d48dc6584237b02` 的 `_api.py`、
  `data/_transforms.py`、`features/graph.py`。其余源码、依赖版本、默认
  求解器参数不变；实际导入路径和源码哈希必须核验。
- 完全沿用 E036 的 3 um 球标签、真实 uint16 图像、五近邻、距离阈值
  300、相邻帧、无 TTA、`(5,32,128,128)` 切块与 `(1,8,16,16)` 重叠。
  固定尺度 `(1,1.625,0.40625,0.40625)`。上游 `Affine` 缩放相对位移并
  保留最小坐标，不另改为绝对原点缩放。距离和其他阈值不扫描。
- 只删除 HOCT 不支持的普通边。保留全部 E029 节点、原坐标和分裂的两条
  子边；精确重合位置继续只用最小 ID 代表输入，并保护所有重合身份关联边。
  不补点、不重连、不与 E039/E040 或公榜失败的 E031/E035 合并。

## 技术前置条件与预算

[S220 CPU 审计](HOCT_SCALE_AUDIT_20260924.md)已在同一服务器分别通过
旧版与修复版的合成候选/帧/切块/体积检查。整个资产审计因独立的 v1 下载
失败而退出；E041 只依赖已通过的尺度子检查和既有 v0，不使用 v1 权重。

先固定两部技术影片 `44b6_eb2880fc`、`6bba_969618f6`，各完整 100 帧，
两张 RTX 4090 分片、每部 900 秒硬上限。技术检查要求完整推理、来源验证、
映射/图拓扑有效、控制评分复现、原节点与分裂边不变；增益不用于选择参数。
通过后保持相同源码协议完成原 64 部，再做既定作者选片排除审查。
不读取隐藏测试标签，不按影片挑选模式。新预测全部完成后才评分。
整个技术任务上限 1 小时，完整比较上限 4 小时；任一失败或超时均不以原
图回退冒充成功。原四项几何/身份/分裂语义测试先在服务器通过，才进入推理。

## 推进判定

沿用完整 64 部总分至少提高 `0.001`、调整后边分数不降、两类胚胎及交替
两半均为正、受影响影片胜多于负且中位增益为正。另要求修复版完整官方
总分高于缓存旧 E036 的 `0.9100497869496292`，以证明相较旧库确有收益。
旧候选图也在相同评价过程中重新评分，仅复用其预测。

排除 E029 作者可见选片中的五部后，59 部全体和两胚胎增益仍须为正：
`44b6_12dfb391`、`44b6_267148e4`、`44b6_2a2eff9f`、
`44b6_341df25f`、`6bba_09961292`。HOCT 参考作者所述 20 部选片名单
尚不完整，训练重叠也未知；此处仍是开发证据，不声称完全独立留出。

任何门槛失败都保留负结果，不调距离、体素尺度、删除比例或求解参数再试。
只有完整开发与输出审查通过，才准备正式 Kaggle 运行；最终仍以公榜回执
检验是否超过 E029 的 0.947 和前 10% 名次。E041 本身不生成正式提交。
