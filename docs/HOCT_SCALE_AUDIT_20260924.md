# HOCT 尺度与 v1 资产复查

本次复查在新的真实影片推理和质量分数之前固定。E036/E037 的历史结果保持
原样；此处只检查其依赖库的尺度处理及此前未取得的 v1 权重。

## 静态来源证据

[官方尺度修复 PR #6](https://github.com/royerlab/hoct/pull/6)于 2026-09-17
合并，对应提交 `8709ee9d3c4d7aae1f022b259d48dc6584237b02`。
E036/E037 使用的 [PyPI 0.2.0](https://pypi.org/project/hoct/0.2.0/)
wheel 发布于 2026-08-26，SHA256 为
`c6194e81a05d272913dd0945ede2484d9a7d89f8d751c4eb1e30c43031e9093c`。
两者逐文件比较确认，wheel 中共有的源码只有以下三个文件发生变化：

- `features/graph.py`：原版计算了局部数据表的 `scaled_*`，但未注册到图，
  也未传给 `DistanceEdges`；修复版注册属性并明确用缩放坐标构造候选边。
- `_api.py`：原版未将 `predict(scale=...)` 传到数据集；修复版在可选 TTA
  之前增加固定的逐轴尺度变换。
- `data/_transforms.py`：扩展 `Affine`，支持每轴固定尺度，作用于坐标、
  体积及相关形状特征。

本项目确实调用 `predict(scale=(1,1.625,0.40625,0.40625), ...)`，且未对
上述库函数做尺度补丁，因此静态调用路径涉及该问题。尚不能据此量化实际
图变化或质量影响，也不能将旧开发结果自动重命名为修复版结果。

固定提交的官方源码归档 SHA256 为
`733d9c70e9e51103156cfc987b216bb73ea6f5138d74403c4d207ba277ad72f6`。
私有审查包从已核验 wheel 复制两个独立源码目录，只在修复目录替换这三个
上游原文件。wheel 生成的版本字符串仍是 0.2.0，另用提交与逐文件哈希
区分修复目录，禁止仅凭版本字符串认定两者相同。

## 固定 CPU 技术检查

`kaggle/check_hoct_scale.py` 的初始执行目标是 Kaggle CPU，服务器恢复后支持
指定服务器 CPU；本地仅作源码打包。Notebook 私有、无 GPU、无比赛输入，
联网只获取官方固定依赖与权重。
全部源码提交并推送后才能打包；子进程总预算 840 秒、Notebook 900 秒。

1. 构造两帧三个合成立方体标签，源位置为 `(z,y,x)=(8,24,24)`，两个
   后继分别为 `(14,24,24)` 和 `(8,36,24)`。固定距离阈值 8、五近邻、
   相邻帧；物理位移分别为 9.75 和 4.875 um。旧版与修复版分别应呈现
   体素距离和物理距离的候选选择。这一人为小阈值只用于单位反例，并非
   真实影片的调参或实验配置。
2. 检查实际 `FrameDataset` 和单块 `TiledRoiDataset` 的节点位置、有限
   特征、无标签内容。切块坐标须先减去 `apply_tiled` 给出的体素块起点；
   上游 `Affine` 保留坐标最小值，实际约定为
   `(u - min(u)) * scale + min(u)`，其中 `u` 为块内坐标。分别检验相对位移
   的物理尺度和该最小值锚定约定，额外报告是否等于直接 `u * scale`；
   二者不可混称。固定变换应确定性地缩放体积。节点输出图的原坐标
   仍用于身份映射。不运行神经网络前向或 ILP 求解。
3. 从[官方 v1 发布](https://github.com/royerlab/hoct/releases/tag/weights-v1)
   下载完整 25,496,698 字节 `general_v1.pt`，核验 SHA256
   `5bd836dfcb15ad796ea79a9595841a3e73b650a71c4acba3fc66aac65d745b33`，
   仅在 CPU 加载 TorchScript，记录参数数量、输入维度和前向签名。
   权重存在或接口相同均不构成改进证据。

检查若证实尺度差异，后续应先固定 v0 权重，独立比较尺度修复的作用；v1
质量评估必须单独定义。仍需两部完整影片技术检查和固定 64 部官方配对比较，
保留原定晋级条件及作者选片排除审查。合成输入检查不提供评分，也不授权
放宽既有门槛或跳过全量验证。

## 状态

第 1 版私有 CPU 检查在 42.32 秒后因审计脚本的切块坐标断言停止：脚本
错误地把相对块起点的坐标直接与全局坐标比较。此前旧版候选边断言和普通
帧数据集检查已通过；修复版和 v1 加载尚未执行，不能称为完整检查成功。
已修正这一检查约定，单独记录块起点、实际与期望坐标，应用于第 2 版。

第 2 版在 56.98 秒停止，旧版全部检查通过，修复版候选边正确选择了
4.875 um 的 Y 方向后继；普通帧数据集的绝对坐标检查未通过。诊断输出及
上游源码进一步确认 `Affine` 保留最小坐标：Z 位移 `6→9.75`、Y 位移
`12→4.875`，但坐标起点仍为原来的 `(8,24,24)`。因此绝对原点直接缩放的
原断言不符合上游约定，不能把这一差异隐藏成“全部绝对坐标物理化”。
后续检查按上述明确公式验证相对尺度与起点，保留直接缩放是否成立的独立字段。
