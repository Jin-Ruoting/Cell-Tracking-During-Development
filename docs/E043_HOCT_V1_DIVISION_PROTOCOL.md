# E043：v1 共识对分裂边的独立删边检验

在 E042 v1 的首次完整影片评分前预注册。与
[E042](E042_HOCT_V1_PROTOCOL.md)共享已固定的 v1 推理结果，但单独检验
分裂处理，不改变 E042。公开
[HOCT veto 参考](https://www.kaggle.com/code/sjlee101/biohub-lf-hoctveto-div-b)
包含允许删除不受 HOCT 支持的分裂边的分支；本项目旧 v0 的 E037 未通过
开发门槛，不能因作者报告或权重版本更新而认定该分支有效。

可证伪假设：在固定尺度的 v1 共识中，删除不受支持的原分裂子边能够改善
分裂 Jaccard，同时提高相对原 E029 和分裂边受保护的 E042 的官方总分。
若分裂或整体指标不满足以下固定标准，则拒绝这一分支。

## 固定机制和输入

- 不进行额外模型推理，完整复用 E042 的相同权重、图像特征、尺度、候选
  邻居、求解和节点映射结果。先检查其完整技术回执、源码协议、输入、
  权重、逐影片缓存和输出哈希；不接受部分影片或失败回退。
- 从原 E029 图出发，对普通边及分裂子边统一取与 v1 的边交集，沿用已
  审查的 `retain_edges(..., protect_divisions=False)`。精确重合位置的所有
  身份关联边继续保护；不新增边、不移动或删除节点、不改变阈值或求解。
- 报告每部删除的普通边、分裂子边、受影响分裂父节点、分裂 TP/FP/FN
  及官方总分变化。对照包括原 E029 和保护原分裂边的 E042 v1；三者采用
  同一官方评分器，E042 对照图和评分须重新验证。
- 推理缓存中没有新标签访问。所有缓存已经完成后才生成这个候选并评分，
  不能使用逐片分数决定删边方式。两部和完整 64 部分别使用完成的 E042
  技术运行与完整运行，依赖内容不可变。

## 执行和判定

先复用固定两部 100 帧技术缓存，验证导出、原节点身份与坐标、允许删除的
边集合、拓扑及控制评分。技术检查不以增益筛选参数；通过后执行相同源码
协议的完整 64 部。CPU 运行，技术检查上限 30 分钟，全量上限 2 小时；
不重复占用 GPU，不创建正式比赛提交。

完整 64 部必须满足既定七项标准：相对原 E029 总分至少增加 `0.001`，
调整后边分数不降，两胚胎及交替两半增益均为正，受影响影片胜多于负且
中位增益为正。另要求：

1. 分裂 Jaccard 严格高于原 E029 和 E042（E042 保留原分裂分量）。
2. 官方总分严格高于 E042 的分裂保护版本。
3. 排除 E029 作者可见五部选片后，59 部全体及两胚胎相对 E029 的总分
   增益均为正。五部清单与 E041/E042 相同，不增删或另选子集。

完整训练重叠和参考作者的 20 部选片仍未知，此处属于开发验证。任何门槛
失败均保留负结果，不改成按胚胎/影片选择保护或删除，不放宽交集条件，
不与其他组件合并重选。只有完整开发和正式输出审查均通过，才单独检验
公榜是否超过当前最好 0.947 并进入前 10%。
