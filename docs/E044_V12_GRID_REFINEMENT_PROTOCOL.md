# E044：固定图上的整数锚点细化

在首次本方案完整影片预测和标签评分之前固定以下比较。[公开 v12 源码](https://www.kaggle.com/code/hengck23/end2end-cell-linker-raw-edge-ja-0-9-no-ilp)的
`max_pool_peak` 以 `nonzero()` 产生整数网格峰值，`refine_node_peak` 在该
位置采样三维残差并相加。S230 只检验了将同一函数用于 E029 连续网格
坐标的接口，四帧存在一个越界输出；不将该输出作为此方案的候选。

本实验检验预训练定位头能否改善原 E029 图的节点匹配，保持所有节点 ID、
时间、边和度数不变。它不是作者完整检测与关联流程，不主张复现其训练损失；
公开 `loss_and_metric_v12.py` 仅包含检查点兼容用字典类，未提供可审查的
实际损失实现。E032 的坐标校准负结果和 E040 的零增益结果继续保留。

## 模型、坐标与三个固定比较组

- 使用与 E040/S230 相同的固定 v12 权重、源码、图像分位数、`[1,4,4]`
  步长和 FP32 推理；不运行检测头、连接头，不训练、不筛选阈值。
- 原始组直接复用 S210（技术检查）或 S213（完整比较）的冻结云端 E029。
  以已完成回执、CSV 哈希、原源码、环境版本和两个锚点分数核验，不重新
  推理控制，也不将服务器与云端差异当作增益。
- 取整组：原始整数体素坐标除以 `[1,4,4]`，按最近偶数规则取整，并将
  **采样索引**约束在 `[0,63]`；乘回下采样步长，作为整数锚点对照。
- 细化组：在同一整数锚点运行作者 `refine_node_peak`，乘回步长后按最近
  偶数规则输出整数体素坐标。额外的 logit 残差不用于筛选或改写节点。
  只执行一次，不混入 E040 交换、HOCT 共识或其他候选。

三组的节点数、ID、时间、边及原顺序一致，仅后两组允许 Z/Y/X 变化。
全部 100 帧和所有节点参与；无节点的帧显式记录，不合成节点。

## 固定有效性规则

1. 原坐标必须有限、为整数且处于图像内。非有限图像、模型残差或不完整
   帧覆盖使任务失败，不用默认值掩盖计算错误。
2. 同一帧有多个节点映射到同一整数锚点时，全部保留原位置，包括原本
   坐标重合的节点。该局部场无法区分这些节点，不再尝试其他采样点。
3. 每个比较组独立检查其提议坐标。连续提议或最终取整坐标越界时保留
   原位置，不裁剪模型输出，不限制或拟合位移幅度。
4. 提议位置若等于其他原始位置，或多个不同原始位置提议到同一整数
   位置，则相关提议全部撤回。原始重合关系可以保留，禁止产生新的重合。
   检查同时完成，不能依节点遍历顺序决定结果；最终独立审计重合关系。

记录各原因的计数、实际改变节点数、位移分布、逐帧输入/输出哈希和耗时。
两个适配组都采用以上规则，不按影片选择哪一组用于候选。

## 执行顺序与判定

先在服务器运行数据无关的语义检查，覆盖坐标单位、取整、边界回退、
锚点冲突、提议冲突、顺序无关和图字段保护。所有代码仅在本地修改、提交
并推送，服务器仅干净 `git pull --ff-only` 后运行检查并记录日志。

随后在私有、离线、固定镜像的 Kaggle 双 T4 上完成既定两部全 100 帧
技术检查。两部结果只验证兼容性、时限和控制复测，不决定参数、方案选择或
是否有足够增益。使用同一协议完成固定 64 部开发比较；所有三个组的图
输出冻结后才开始官方标签评分。技术上限 1800 秒、完整上限 7200 秒，
执行前核查免费额度；不购买资源，不并发重复同一个实验。

细化组晋级必须同时满足：

- 相对原 E029 的完整 64 部总分增益至少 `0.001`，调整后边分数不下降，
  两胚胎和交替两半增益均为正，受影响影片胜多于负且中位增益为正。
- 节点召回率不下降；虽然图中分裂边保持原样，定位变化仍可能改变官方
  分裂匹配，因此完整分裂 Jaccard 不得下降。
- 相对只取整对照的完整总分严格增加，证明收益不仅来自取整。
- 在与 E040 相同的 58 部作者选片排除集合中，相对原 E029 的全体和两
  胚胎增益均为正。该集合仍为开发敏感性分析，不是独立或训练不重叠验证。
- 实际节点坐标发生变化，所有边逐字段相同，节点/坐标/拓扑审计通过。

未通过即拒绝，不按影片混合两组，不改边界、锚点或位移规则重新筛选。
取整组仅用于解释细化机制，不作为本协议下可择优提交的第二候选。
通过开发门槛后才安排完整输出审计与公榜验证；目标是否达到取决于实际
公榜回执和名次，接口检查与开发分数不能替代该证据。
