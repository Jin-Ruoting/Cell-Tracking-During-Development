# E040：固定节点上的独立关联检验

在首次 E040 图像关联输出和标签评分之前固定本方案。假设是：v12 的独立
多尺度外观特征和跨帧注意力，可纠正 E029 中部分两细胞身份交换；保持检测
坐标、节点数及所有节点度数不变，可将比较集中到关联信息。

这是本项目设计的组件实验，并非作者完整 v12 跟踪流程的复现，也未得到
优于 E029 的质量证据。v12 自行检测出的越界坐标不进入此实验；新方案直接
采样 E029 的原坐标，不移动、裁剪、添加或删除节点。

## 单次交换规则

原边为 `a→b`、`c→d`，仅考虑两个源都只有一条出边的情况。只有以下条件
全部成立，才同时替换为 `a→d`、`c→b`：

1. 在完整相邻帧矩阵中，`a` 唯一最优目标为 `d`、`c` 唯一最优目标为 `b`，
   且 `d` 唯一最优来源为 `a`、`b` 唯一最优来源为 `c`。相等最高值全部弃用。
2. 两条新边 logits 均大于固定空连接 logit `0`；该基准沿用作者演示。
3. 新边 logit 之和减去旧边之和至少为 `ln(9)`。这是评分前固定的强偏好
   门槛，不是校准后的正确概率，也不是根据技术影片选择出的参数。
4. 两条新边的物理距离均不超过 `5.5 um`，沿用 E029 固定紧连接距离。

唯一互选的两环互不共享端点，单次同时应用；不做迭代、不处理更长环、
不在拒绝后寻找次优替代。总边数、每个节点入度和出度、原有分裂边必须
逐项不变；缺失端点、重复边、非法坐标或不完整 logits 直接失败。

## 检查与资源

1. 数据无关语义测试检查成功交换、非互选/并列/空连接/弱偏好/过远拒绝、
   分裂保护、完整候选池、长环不改写、节点 ID 与矩阵次序无关、非法输入失败。
2. 私有离线 Kaggle CPU 先检查两部影片各第 0、1 帧，FP32、4 线程；子进程
   20 分钟、Notebook 25 分钟上限。报告节点数、logit 范围、交换计数/原因、
   原图不变性、时间和内存，不计算标签分数。其是否出现交换不选择参数。
3. 后续使用固定 T4/FP32、关闭 TF32，先完成两部全 100 帧技术流程；再按
   实测预算安排一次完整 64 部比较，最多 8 小时，不并发复制相同任务。
   CPU 四帧检查不能代替 GPU 全流程。启动前刷新免费额度，不购买资源。
4. 完整图审查应证明节点逐字段相同、度数和分裂边不变、真正改变的普通边数、
   完整 100 帧覆盖、控制/候选哈希在评分期间不变。复用控制须明确记录来源。

## 完整判定

只以 64 部完整官方比较判定：总分增益至少 `0.001`、调整后边分数不下降、
两类胚胎和交替两半增益均为正、受影响影片胜多于负且中位增益为正。还需
验证分裂 TP/FP/FN 与原图完全一致，且确有边发生变化。失败即拒绝，不改
距离、偏好门槛或互选规则重新筛选。

通过后额外在 58 部可见作者选片排除集合上检查全体与两胚胎增益均为正。
排除 `44b6_12dfb391`、`44b6_267148e4`、`44b6_2a2eff9f`、`44b6_341df25f`、
`44b6_949adeb1`、`6bba_09961292`。训练影片重叠仍未知，这只是开发敏感性
审查，不是独立验证。正式提交还需完整运行输出审计，并以实际公榜回执检验
