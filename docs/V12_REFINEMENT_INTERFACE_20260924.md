固定使用 [v12 作者源码和演示](https://www.kaggle.com/code/hengck23/end2end-cell-linker-raw-edge-ja-0-9-no-ilp)
以及已核验的同一检查点。源码 `model_v12.py` SHA256 为

`ecd8869de9cf405c1a93a563b4810faad5fd2378f57341e18c4e6b5a87201552`。
作者的细化函数在坐标四舍五入后采样位移场，将残差加到原连续坐标上；
其输出边界仍有未解决的 TODO。这个接口是否适合已有的 E029 节点，尚需实测。

检查只使用既定两部影片 `44b6_eb2880fc`、`6bba_969618f6` 的第 0、1 帧，
及完成并精确复测过的 S210 E029 节点。先验证零残差恒等、最近网格采样、
连续坐标保留和物理位移单位；随后以作者图像归一化和 `[1,4,4]` 下采样
运行已严格加载的 U-Net 与细化头，记录有限性、位移分位数、越界节点和耗时。
原节点、边和控制文件保持不变；不运行检测头或连接头，不导出候选图。

全部模型与图像操作仅在私有、离线 Kaggle CPU 上执行，4 个线程，FP32，
子进程上限 20 分钟、Notebook 上限 25 分钟。本地仅打包已提交且推送的源码。
不读取 GEFF、示例或隐藏测试图像，不训练、调参或计算质量分数，也不裁剪
越界坐标。接口完成和全部坐标有效分别记录，不能将 `passed` 当作质量通过。

本检查不构成正式提交依据。后续若进入完整实验，须先定义
边界处理、比较组和固定 64/58 部官方评分门槛，再以两部完整影片检查和
完整配对结果判定。当前 E040/E042 的预测、分数与阈值均保持各自冻结协议。

入口为 `kaggle/check_v12_refinement.py package|run`。云端回执位于
`/kaggle/working/logs/v12-fixed-refinement`；原始源码、权重和回执不加入公开 Git。
